# ADR-008: Internationalization — English, Sinhala, Tamil

**Status:** Accepted
**Date:** 2026-11-16
**Deciders:** human

## Context

AutoLanka operates in Sri Lanka with three official languages:
- **English** — business, tourism, educated population
- **Sinhala** — majority language (~75% of population)
- **Tamil** — minority language (~25%), Northern/Eastern provinces

Must support RTL-ready layout for future Arabic/Urdu expansion.

## Decision

Use **i18next + react-i18next** (frontend) and **NestJS i18n module** (backend) with **JSON resource files**.

### Structure

```
apps/web/public/locales/
  ├── en/
  │   ├── common.json
  │   ├── auth.json
  │   ├── services.json
  │   └── errors.json
  ├── si/
  │   └── (same keys, Sinhala translations)
  └── ta/
      └── (same keys, Tamil translations)

apps/api/src/i18n/
  ├── en.json
  ├── si.json
  └── ta.json
```

### Key decisions

| Aspect | Choice |
|---|---|
| Default language | English |
| Detection order | `localStorage` → `Accept-Language` → `en` |
| Language switcher | Persists to `localStorage` + cookie |
| Pluralization | ICU MessageFormat via i18next |
| Date/number formatting | `Intl.DateTimeFormat` / `Intl.NumberFormat` per locale |
| Currency | LKR for all; `new Intl.NumberFormat(locale, { style: 'currency', currency: 'LKR' })` |
| RTL support | `dir="rtl"` on `<html>` when locale is RTL (future); CSS logical properties |

### Translation workflow

1. **Dev**: Add keys to `en` files; CI fails if `si`/`ta` missing keys
2. **Translate**: CSV export → translator → CSV import (scripts/i18n-sync.sh)
3. **Review**: Native speaker review before merge
4. **Missing key fallback**: Show English key in brackets `[key.name]`

## Consequences

**Positive:**
- i18next ecosystem mature; works with React/Vite/Netlify
- NestJS i18n module integrates with pipes/guards
- ICU MessageFormat handles complex plurals (Sinhala/Tamil have 2 forms)
- JSON files = version control friendly, diffable
- Lazy-loading locales via dynamic import

**Negative:**
- Three languages = 3x translation effort
- Sinhala/Tamil fonts increase bundle size (subset via `fontsource`)
- RTL CSS logical properties need discipline (`margin-inline-start` not `margin-left`)
- Date formats differ: EN `DD/MM/YYYY`, SI `YYYY/MM/DD`, TA `DD/MM/YYYY`

## Alternatives considered

| Option | Rejected because |
|---|---|
| FormatJS / react-intl | Heavier; ICU runtime; i18next lighter |
| LinguiJS | Good but smaller community; CLI extra step |
| Custom solution | Reinventing pluralization, interpolation, fallbacks |
| Single language (English) | Excludes majority of Sri Lankan users |
